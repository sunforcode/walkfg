## Context

当前 Flutter Web 在引擎首帧前展示通用加载提示，首帧后又等待基础设施初始化才进入首页。首页自身还会读取本地路线选择并异步请求路线、轨迹和天气。用户真正需要的是尽早看到首页壳层，数据加载只更新局部内容。

## Goals / Non-Goals

**Goals:**

- HTML 阶段和 Flutter 第一帧阶段都呈现首页语义。
- 非必要初始化与首页壳层渲染解耦。
- 首页业务数据在基础初始化完成后加载。
- 减少第三方阻塞资源和重复主 JS 传输。

**Non-Goals:**

- 不改变首页视觉设计、业务接口或路线选择规则。
- 不延迟用户主动触发功能所必需的初始化。
- 不在本次引入 CDN 或替换 Flutter 渲染器。

## Decisions

应用配置在 `runApp` 前同步建立，因为它仅读取编译期常量且网络层构造依赖它。其余异步初始化在 `runApp` 后启动，并通过共享 Future 传给首页。首页在 Future 完成前显示现有 `EmptyHome`，完成后再执行当前 `_loadHomeData`。

Web HTML 使用无图片、无外部字体的 CSS 首页壳层。它不模拟完整交互，只提供与 Flutter 首页一致的背景、品牌和主文案，并在 Flutter 第一帧时移除。

删除未被 Dart 代码引用的 MapLibre 全局脚本和样式。`main.dart.js` 不再使用 `no-store`，改为 `no-cache`，允许浏览器保存副本并通过 ETag 重新验证；HTML 和 bootstrap 仍保持不可复用旧版本。

## Risks / Trade-offs

- 首页壳层显示时“找路线”尚不能操作 → HTML 壳不伪造按钮交互，Flutter 首页出现后恢复真实交互。
- 初始化失败时首页已显示 → 保留启动错误回调能力，当前首页数据请求将呈现已有错误态。
- 路线数据比以前稍后开始 → 它不再阻塞首页本身，用户感知更稳定。
