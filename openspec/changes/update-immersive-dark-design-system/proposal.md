# Change: 建立沉浸式暗色设计系统与 UI 开发工作流

## Why

当前 Flutter App 已经在首页形成了较明确的暗色沉浸式方向，但路线、行程、攻略、装备、天气和个人中心仍混用亮色卡片、Cupertino 默认样式、局部暗色样式以及页面私有常量。现有 `design-system` Spec 仍以亮色天空蓝和仪表盘卡片布局为基准，与实际首页方向和当前 Token 不一致，因此无法作为开发者或 Agent 的可靠约束。

本变更将首页体现的“大幅户外影像、超大标题、内容叠图、暗色渐变遮罩、轻量毛玻璃控件”确立为 Walk 的主视觉语言，并建立可复用公共组件和固定 UI 开发工作流，使后续 Agent 优先遵循 Spec 和复用组件，而不是继续在页面内创建新的视觉实现。

## What Changes

- 将 Flutter App 的默认视觉基准从亮色天空蓝卡片体系改为沉浸式暗色体系，并在变更归档时同步重写 `design-system` Spec 的 Purpose 与设计风格说明。
- 将“全屏封面式大图”定义为内容型页面的主视觉模式，适用于首页、路线发现、路线详情、攻略和行程入口等强调目的地与户外内容的页面。
- 将工具型页面定义为同源暗色模式，适用于装备编辑、表单、设置和高密度信息页；这些页面共享相同 Token 与组件，但不强制使用大图。
- 统一暗色颜色、文字层级、渐变遮罩、间距、圆角、毛玻璃、动效和影像可读性规则。
- 建立公共组件分层，包括沉浸式页面骨架、Hero 影像、渐变遮罩、叠图标题、指标组、毛玻璃操作、标准导航、普通暗色页面骨架，以及统一的加载、错误、空态和网络图片组件。
- 建立 Agent 固定 UI 工作流：读取 Spec 和公共组件目录，识别页面类型，搜索可复用组件，优先组合或扩展公共组件，仅在确认无法复用时创建局部组件，并完成聚焦验证。
- 要求新增公共组件具备明确语义、受控变体、示例或 Widget 测试，禁止通过无限参数形成万能组件。
- 制定渐进迁移顺序，优先处理视觉断层最大的 Trip 和 Guide，不要求一次性重写全部页面。

## Impact

- Affected specs: `design-system`, `ui-development-workflow`（新增）
- Affected code: `lib/theme/**`, `lib/ui/page/common/**`, `lib/ui/widget/**`, 各业务页面 UI
- Affected governance: `walk/AGENTS.md` 或等价 Flutter UI 开发规则、UI 代码审查与测试约束
- No impact: 后端 API、DTO、业务数据模型、持久化和跨端接口

## Approval Gate

本提案获确认前不修改 Flutter 实现。批准后按 `tasks.md` 分阶段执行，每阶段保持业务行为不变并运行聚焦 Widget 测试、`flutter analyze` 与相关回归检查。
