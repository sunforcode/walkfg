# Design: 前端设计系统升级

## Context

Walk 是一款徒步工具应用，需要展示大量路线、行程、装备等数据。当前设计系统已建立基础 Token，但缺乏信息架构和交互模式的规范化定义。

**核心设计原则**:
- **工具属性优先**: 高效、专业、信息密度适中
- **渐进式展示**: 概览 → 列表 → 详情的多层次架构
- **现代化交互**: 符合主流 APP 的使用习惯

## Goals / Non-Goals

**Goals**:
- 建立统一的信息架构规范
- 定义页面布局模式和组件规范
- 规范现代化交互模式
- 扩展现有 Design Token

**Non-Goals**:
- 不改变现有配色方案（天空蓝调）
- 不重构现有业务逻辑
- 不涉及深色主题（后续独立变更）

## Decisions

### Decision 1: 三层信息架构

```
┌─────────────────────────────────────────┐
│  第一层：概览层 (Overview)                │
│  ├── 统计数据快速扫一眼                   │
│  ├── 关键指标突出显示                    │
│  └── 快捷入口直达功能                    │
├─────────────────────────────────────────┤
│  第二层：列表层 (List)                   │
│  ├── 卡片/列表展示多项内容               │
│  ├── 核心参数一目了然                    │
│  └── 支持筛选/排序/搜索                  │
├─────────────────────────────────────────┤
│  第三层：详情层 (Detail)                 │
│  ├── 完整信息分区展示                    │
│  ├── Tab/Segment 切换不同维度           │
│  └── 支持展开/折叠次要信息               │
└─────────────────────────────────────────┘
```

**理由**: 符合用户从宏观到微观的信息获取习惯，减少认知负担

### Decision 3: 核心组件规范

#### 3.1 统计卡片 (StatCard)
```dart
// 用于首页概览的关键数据展示
StatCard(
  icon: Icons.route,
  label: '总里程',
  value: '128.5',
  unit: 'km',
  trend: StatTrend.up,  // 可选：趋势指示
)
```

**视觉规范**:
- 尺寸：等分宽度，固定高度 80-100dp
- 布局：图标 + 数值 + 单位 + 标签
- 数值：大字号突出 (24-28sp)
- 单位/标签：小字号弱化 (12-14sp)

#### 3.2 数据卡片 (DataCard)
```dart
// 用于列表页的内容卡片
DataCard(
  thumbnail: Image(...),  // 可选缩略图
  title: '五台山大朝台',
  subtitle: '山西忻州 · 中等难度',
  metrics: [
    DataMetric(icon: Icons.straighten, value: '68km'),
    DataMetric(icon: Icons.terrain, value: '3058m'),
  ],
  miniChart: ElevationMiniChart(...),  // 可选迷你图表
  onTap: () => ...,
)
```

**视觉规范**:
- 圆角：8dp (AppRadius.md)
- 内边距：16dp (AppSpacing.md)
- 缩略图：16:9 或 1:1 比例
- 指标区：水平排列，图标 + 数值

#### 3.3 可展开区块 (ExpandableSection)
```dart
// 用于详情页的折叠内容
ExpandableSection(
  title: '详细信息',
  initiallyExpanded: false,
  child: Column(...),
)
```

#### 3.4 操作栏 (ActionBar)
```dart
// 底部固定操作栏
ActionBar(
  primary: ActionButton(
    label: '开始导航',
    onPressed: () => ...,
  ),
  secondary: [
    ActionButton.icon(Icons.share, onPressed: ...),
    ActionButton.icon(Icons.bookmark, onPressed: ...),
  ],
)
```

### Decision 4: 交互模式规范

#### 4.1 加载状态
- **初次加载**: Skeleton 骨架屏
- **刷新加载**: 下拉刷新指示器 (CupertinoSliverRefreshControl)
- **加载更多**: 列表底部加载指示器
- **操作加载**: 按钮内置 loading 状态

#### 4.2 过渡动效
- **页面切换**: 系统默认 (iOS: 右滑入, Android: 上滑入)
- **卡片点击**: 轻微缩放反馈 (scale: 0.98)
- **Tab 切换**: 横向滑动过渡
- **展开/折叠**: 高度动画 (300ms, easeInOut)

#### 4.3 手势交互
- **列表**: 上下滑动滚动，下拉刷新
- **详情页**: 左滑返回 (iOS)
- **底部抽屉**: 拖拽展开/收起
- **图片**: 双指缩放，单击查看大图

### Decision 5: Design Token 扩展

#### 5.1 新增字体样式
```dart
// 数据展示专用
static const TextStyle statValue = TextStyle(
  fontSize: 28,

static const TextStyle statUnit = TextStyle(
  fontSize: 12,

  fontSize: 14,
  fontWeight: FontWeight.w600,

```

#### 5.2 新增阴影层级
```dart
// 卡片层级阴影
static const List<BoxShadow> cardElevation1 = [...]; // 普通卡片
static const List<BoxShadow> cardElevation2 = [...]; // 悬浮卡片
```

#### 5.3 新增交互状态颜色
```dart

static const Color hovered = Color(0x05000000);    // 悬停态
static const Color focused = Color(0xFF2196F3);    // 聚焦态边框
```

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 组件过多导致维护成本增加 | 优先实现核心组件，按需扩展 |
| 现有页面适配工作量 | 渐进式迁移，新页面优先使用新规范 |
| 设计规范与实现不一致 | 建立组件文档和示例页面 |

## Migration Plan

1. **Phase 1 - 规范建立** (本次变更)
   - 更新 design-system spec
   - 实现核心 Design Token 扩展

2. **Phase 2 - 组件实现**
   - 实现基础组件 (StatCard, DataCard 等)
   - 创建组件示例页面

3. **Phase 3 - 页面适配**
   - 新页面直接使用新规范
   - 现有页面逐步迁移
