# Route Detail Page Redesign - Design Document

**Date**: 2026-01-17  
**Version**: Final

## Design Philosophy

新的路由详情页设计遵循以下设计原则：

### 1. **清晰的优先级** (Clear Hierarchy)
- 三层优先级架构，用户按顺序回答三个问题
- 信息权重分明，避免用户迷失于细节
- 第一优先级必须展开，二三优先级按需展开

### 2. **简洁性** (Simplicity)
- 移除传统 Tab 栏的视觉复杂度
- 采用可折叠卡片，用户按需展开信息
- 避免过多层级和冗余视觉元素

### 3. **优雅性** (Elegance)
- 平滑的展开/折叠动画 (300ms)
- 和谐的色彩搭配（蓝色主题 + 白色卡片）
- 充分的空白和间距设计

### 4. **交互性** (Interactivity)
- 地图与信息的单向联动（仅信息→地图）
- 实时反馈用户操作（列表项高亮 + 地图提示）
- 直观的交互逻辑，无歧义

### 5. **品牌一致性** (Brand Consistency)
- 符合 Strava、AllTrails、Apple Health 等参考应用的设计风格
- 专业运动风格，天空蓝调
- 遵循项目 Design System

## Information Architecture

### 用户的三个核心问题

```
问题1："这条路长什么样，我想走吗？"
├─ 地图头图（完整轨迹）
├─ 概览（难度、距离、海拔、时间）
└─ 每日行程 ⭐ 主角（按天规划，住宿信息）

问题2："难度如何，我能走吗？"
├─ 路线分段 ⭐ 辅助（子段难度分布）
└─ 户外资源（水源、营地、补给）

问题3："我如何准备？"
├─ 装备建议
├─ 用户评论和照片
└─ 相关路线推荐
```

### 优先级定义

| 优先级 | 区块 | 默认状态 | 目的 |
|--------|------|--------|------|
| P0 | 地图、概览 | Expanded | 快速判断 |
| P0 | 每日行程 ⭐ | Expanded | 了解节奏和住宿 |
| P1 | 路线分段 ⭐ | Collapsed | 补充难度信息 |
| P1 | 户外资源 | Collapsed | 资源可用性 |
| P2 | 装备建议 | Collapsed | 季节性准备 |
| P3 | 用户内容 | Collapsed | 社区参考 |
| P3 | 相关路线 | Collapsed | 发现新线路 |

## Visual Hierarchy

### 信息层级

```
级别1 (最高优先级) - 决策关键
├─ 地图（路线轨迹）
├─ 路线名称、关键指标
└─ 每日行程时间轴 ⭐ 主角

级别2 (重要)
├─ 路线分段简轴 ⭐ 辅助
└─ 户外资源（水源+营地+补给合并）

级别3 (参考)
├─ 装备建议

级别4 (扩展)
├─ 用户评论和照片
└─ 相关路线
```

### 视觉实现

1. **地图**：占据屏幕上半部分，展示完整轨迹，蓝色系设计
2. **标题**：大字体 (24sp)，粗体，关键指标紧跟其后
3. **每日行程**：时间轴式，数字标记 (1️⃣ 2️⃣ 3️⃣) + 简洁描述，支持点击展开详情
4. **路线分段**：简轴显示（月字条格式），折叠状态下所有段一行展示
5. **可折叠卡片**：白色背景，轻微阴影，清晰的展开/折叠指示

## Color Palette

### 主色系
- **主色**: AppColors.primary (#2196F3) - 天空蓝
- **浅色变体**: AppColors.primaryLight (#64B5F6)
- **深色变体**: AppColors.primaryDark (#1976D2)

### 背景和文字
- **页面背景**: AppColors.background (#FAFAFA) - 极浅灰
- **卡片背景**: AppColors.surface (#FFFFFF) - 纯白
- **主文字**: AppColors.textPrimary (#212121) - 深灰/黑
- **副文字**: AppColors.textSecondary (#757575) - 中灰
- **提示文字**: AppColors.textHint (#BDBDBD) - 浅灰

### 互动反馈色
- **高亮**: AppColors.primary (链接、按钮)
- **成功**: AppColors.success (#4CAF50) - 绿色
- **警告**: AppColors.warning (#FF9800) - 橙色
- **错误**: AppColors.error (#F44336) - 红色

### 使用场景
- 分类标题：AppColors.textPrimary
- 内容文字：AppColors.textPrimary
- 描述文字：AppColors.textSecondary
- 分割线：AppColors.divider
- 卡片边框：AppColors.divider
- 链接：AppColors.primary
- 高亮状态：AppColors.primaryLight (5% 透明度)

## Typography & Spacing

### 字体设计

**标题层级**:
1. 路线名称: DisplaySmall (24sp, bold)
2. 分类标题: HeadlineSmall (18sp, semiBold)
3. 项目标题: TitleMedium (14sp, semiBold)

**正文层级**:
1. 卡片内容: BodyMedium (14sp, regular)

**间距规范**:
- 页面边距: AppSpacing.xl (32dp) 或 AppSpacing.lg (24dp)

- 卡片: AppRadius.md (8dp) - 方正现代风格

## Animation & Motion

### 展开/折叠动画

**参数**:
- 时长: 300ms
- 缓动: Curves.easeInOut
- 箭头旋转: 0° → 90°

**关键帧**:
```
0ms:   height: 0, opacity: 0, rotation: 0°
150ms: height: 50%, opacity: 0.7, rotation: 45°
300ms: height: 100%, opacity: 1, rotation: 90°
```

### 点击反馈

**分类标题点击**:
- 背景色变浅（AppColors.primary 4% 透明度）
- 时长: 200ms
- 缓动: Curves.easeInOut

**列表项点击**（地图联动时）:
- 背景色变浅（AppColors.primary 5% 透明度）
- 时长: 300-500ms（保持高亮）

**地图标记高亮**:
- 方式: 闪动或脉冲
- 持续: 1-1.5s
- 缓动: 自定义脉冲曲线

## Interaction Flows

### 流程 1: 用户浏览页面

```
用户进入详情页
  ↓
显示地图头图（完整轨迹）
显示概览和每日行程（默认展开）
其他分类默认折叠
  ↓
用户滚动页面
  ↓
地图逐渐变小（350dp → 150-200dp）
标题区变为 sticky
  ↓
用户点击某个可折叠分类标题
  ↓
该分类平滑展开（300ms 动画）
  ↓
用户继续浏览
```

### 流程 2: 用户点击每日行程某一天

```
用户在"每日行程"时间轴中点击某一天
  ↓
列表项背景色变浅（5% 透明度，300-500ms）
  ↓
地图立即缩放和平移到该天轨迹范围
  ↓
该天起终点在地图上高亮显示
  ↓
1-1.5 秒后恢复正常状态
  ↓
用户可点击另一天，地图无缝更新
```

### 流程 3: 用户点击路线分段某一段

```
用户点击折叠的"路线分段"展开简轴
  ↓
或点击已展开的某一段行
  ↓
列表项背景色变浅（5% 透明度）
  ↓
地图自动缩放到该段轨迹范围
  ↓
该段轨迹和起终点在地图上高亮
  ↓
标记点闪动（1-1.5s）
  ↓
用户可继续交互，无缝衔接
```

### 流程 4: 用户点击户外资源某位置

```
用户展开"户外资源"卡片
  ↓
选择"水源"、"营地"或"补给点"
  ↓
点击某个具体位置
  ↓
列表项高亮（5% 透明度）
  ↓
地图立即标记该位置
  ↓
位置信息弹窗显示（可选）
  ↓
1-1.5s 后自动消失
```

## Design Decisions

### 为什么每日行程是主角？

1. **心理模型** - 用户习惯按"天"规划生活
2. **住宿信息** - 关键的决策因素，只在每日行程中有
3. **时间感** - "未来 3 天的计划"比"分成 5 段"更直观
4. **优先级** - 用户首先想知道"要花几天？每天多远？"

### 为什么路线分段是辅助？

1. **补充信息** - 提供细粒度的难度分布
2. **非替代** - 与每日行程互补而非替代
3. **灵活查看** - 用户在了解日程后可按需查看段信息
4. **保持简洁** - 避免两个维度竞争用户注意力

### 为什么移除 Tab 栏？

1. **现代设计趋势** - Strava、AllTrails 等应用已采用可折叠设计
2. **降低认知负荷** - 无需记住 Tab 标签，直观的标题即可
3. **灵活排序** - 分类顺序可按优先级调整，不受 Tab 限制
4. **视觉简洁** - 减少水平占用，专注内容

### 为什么采用半固定地图？

1. **上下文保持** - 地图始终可见，用户能看到路线全景
2. **空间高效** - 逐渐变小而非完全消失
3. **地图-信息联动** - 用户操作时地图即时反馈
4. **现代模式** - 与谷歌地图、高德地图的交互一致

### 为什么采用单向交互？

1. **简洁高效** - 信息→地图，逻辑清晰
2. **避免复杂** - 不需地图反向触发展开，减少混淆
3. **快速反馈** - 用户点击信息立即看到地图变化
4. **易于学习** - 交互规律直观，无歧义

## Accessibility Considerations

- 所有可交互元素均支持 VoiceOver (iOS 屏幕阅读器)
- 按钮和链接的最小点击区域: 44×44dp
- 充足的色彩对比度 (WCAG AA 标准)
- 清晰的焦点指示器
- 动画可选（支持减少运动设置）
- 时间轴中的数字标记便于扫描

---

## Performance Optimization

1. **列表虚拟化** - 使用 `ListView.builder` 处理长列表
2. **图片懒加载** - 只加载可见区域的图片
3. **地图缓存** - 使用缓存地图瓦片，减少网络请求
4. **动画优化** - 使用 GPU 加速动画，避免频繁重建 widget
5. **标记聚合** - 户外资源标记点过多时进行聚合展示
