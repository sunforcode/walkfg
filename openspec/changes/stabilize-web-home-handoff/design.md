## Context

Web 冷启动当前依次暴露 HTML 空首页、Flutter 空首页和已选路线首页。HTML 缺少初始 viewport，导致移动端先按桌面布局宽度缩小显示；Flutter 又把尚未完成的路线恢复表现为业务空态。路线选择服务在首次恢复非空 ID 时还会通知监听器，与主动首页加载形成重复请求。

## Goals / Non-Goals

**Goals:**

- 冷启动期间只展示中性品牌启动画面，不表达“有路线”或“无路线”。
- 移动端从首个 HTML 帧开始使用设备宽度，避免整体缩放跳变。
- 首次可见的 Flutter 业务页面直接是最终空态、路线态或错误态。
- 首次恢复路线只触发一次首页数据请求。

**Non-Goals:**

- 不重做现有 `EmptyHome` 或 `RouteHome` 视觉。
- 不增加骨架屏、进度条或新的业务入口。
- 不修改后端接口和路线持久化格式。

## Decisions

HTML 启动画面仅保留背景、山体和品牌信息，不显示菜单、“找路线”或“还没有行程”。这些元素都代表可交互或已确定的业务状态，在恢复完成前展示会误导用户。

viewport 必须静态写在 `index.html` 的 `<head>` 中，不能依赖 Flutter 启动后动态注入。这样首个 HTML 帧和 Flutter 都使用同一设备逻辑宽度。

Flutter 在 startup 或首次首页数据 Future 未完成时渲染无业务语义的透明占位。Web 上该区域被静态启动画面覆盖；原生端只保持页面背景，不短暂显示空态。首次 Future 完成后才允许 `EmptyHome`、`RouteHome` 或 `ErrorHome` 成为可见业务页面，并通知 HTML 壳退场。

首次调用 `getSelectedRouteId()` 时，持久化恢复不向现有首页 listener 广播。listener 只用于初始化完成后的真实用户选择变化，避免恢复动作与主动加载产生两个相同请求。

## Risks / Trade-offs

- [首页接口响应慢时品牌启动画面停留更久] → 保持画面轻量稳定；失败时确保切换到可重试错误页。
- [静态壳与最终路线页差异较大] → 使用短淡出过渡，但不插入错误的空首页状态。
- [调整路线恢复通知语义影响其他监听者] → 当前代码仅首页监听该 notifier，并补充首次恢复只加载一次的回归测试。
