# 行程页（TripDetailScreen & TripEditScreen）现状说明

## 一、产品视角

### 1.1 页面定位
- **双页面结构**：行程页分为"详情展示页（TripDetailScreen）"和"编辑页（TripEditScreen）"。
- **功能定位**：
  - **TripDetailScreen**：用于行程的查看、预览、分享、收藏、参考等操作。
  - **TripEditScreen**：用于行程的新建、编辑、完善，仅限有权限的用户（如发起者）进入。
- **用户分层**：
  - **发起者**：拥有编辑、保存、确认、开始、记录、回忆等操作权限。
  - **普通用户**：仅可查看、收藏、参考、分享行程。
- **核心价值**：帮助用户全面了解、管理和复用行程，提升协作与分享体验，支持多角色、多场景的灵活适配。

### 1.2 模式控制
- **展示页（TripDetailScreen）**：
  - **可预览模式**：发起者或参与者可预览行程全貌，部分操作可用。
  - **纯展示模式**：他人行程、历史行程，仅支持只读浏览和部分交互（如收藏、分享）。
  - **操作区**：根据用户身份和行程状态，动态显示"编辑""完成规划""开始行程""收藏""参考此行程""分享行程"等按钮。
- **编辑页（TripEditScreen）**：
  - 仅发起者可进入，编辑完成后返回详情页自动刷新。
  - 顶部导航栏包含"取消"和"保存"按钮，支持未保存更改检测和弹窗确认。

### 1.3 主要内容区域
- **TripDetailScreen**：
  - 地图头部（TripMapHeaderWidget）
  - 行程概览（TripOverviewDisplayWidget）
  - 每日行程（TripItineraryDisplayWidget）
  - 参与者信息（TripParticipantsDisplayWidget）
  - 装备清单（TripEquipmentDisplayWidget）
  - 预算信息（TripBudgetDisplayWidget）
  - 食物饮水（TripFoodWaterDisplayWidget）
  - 交通住宿（TripTransportationDisplayWidget）
  - 天气安全（TripWeatherSafetyDisplayWidget）
  - 操作按钮区（根据身份/状态动态变化）
- **TripEditScreen**：
  - 基础信息编辑（行程名称、描述等）
  - 每日行程编辑（可折叠）
  - 参与者管理（可折叠）
  - 装备管理（可折叠）
  - 预算管理（可折叠）
  - 食物饮水规划（可折叠）
  - 交通住宿预订（可折叠）
  - 安全备注（可折叠）

### 1.4 交互亮点
- **分角色操作**：发起者可编辑，普通用户只读，操作区和按钮根据身份/状态动态变化。
- **状态驱动UI**：行程状态（规划中、已确认、进行中、已完成、已取消）影响页面标题、操作区和内容展示。
- **编辑保护**：编辑页有未保存更改时弹窗确认，防止误操作丢失数据。
- **反馈及时**：所有操作均有Toast提示，提升用户体验。
- **数据联动**：行程与路线、装备、食物、饮水等模块数据联动，信息一体化。

## 二、技术视角

### 2.1 结构与拆分
- **主页面**：
  - TripDetailScreen（StatefulWidget）：负责详情数据加载、导航、权限判断和整体布局。
  - TripEditScreen（StatefulWidget）：负责编辑数据加载、编辑状态管理、保存/取消逻辑。
- **区域组件**：每个功能区域均为独立Widget，职责单一，便于维护和扩展。
  - 展示页：如 TripMapHeaderWidget、TripOverviewDisplayWidget、TripItineraryDisplayWidget 等。
  - 编辑页：如 TripCollapsibleSectionWidget 及其子内容（基础信息、每日行程、装备、预算等）。

### 2.2 技术实现要点
- **Cupertino风格**：全页面采用Cupertino组件，风格统一，原生iOS体验。
- **异步数据加载**：FutureBuilder加载行程详情，支持加载中、错误、空数据三种状态。
- **局部状态管理**：如关联路线、滚动控制器、编辑状态等仅在本页面管理，避免全局污染。
- **权限与状态判断**：通过私有方法判断当前用户身份和行程状态，动态调整UI和操作按钮。
- **页面跳转与数据刷新**：编辑页保存后返回详情页自动刷新，保证数据一致性。
- **操作反馈**：自定义Toast提示，所有操作均有即时反馈。
- **空/异常处理**：所有异步操作均有错误处理和重试机制。
- **编辑保护**：编辑页有未保存更改时弹窗确认，防止误操作丢失数据。

### 2.3 组件复用与扩展性
- 展示页和编辑页大量复用区域组件，提升开发效率和风格一致性。
- 展示页以只读型组件为主，编辑页以可交互/可编辑型组件为主。
- 结构清晰，便于后续功能扩展和维护。

### 2.4 权限与模式控制
- 页面入口参数（如isReadOnly、tripId）和当前用户身份决定页面模式和可操作性。
- 展示页：根据用户身份和行程状态，动态调整操作按钮和可编辑性。
- 编辑页：仅发起者可进入，编辑完成后返回详情页自动刷新。

---

## 三、总结

当前行程页采用"展示页+编辑页"双页面模式，结合灵活的权限与模式控制，满足了多角色、多场景的业务需求。页面结构清晰、组件拆分合理、风格统一，具备良好的可维护性和扩展性。
